# audio 目录说明

只有 `seg/` 一个子目录，里面是**每日听力用的 77 段真题切片**，一天一段，开箱即用。

```
audio/seg/2025-12-1_conversationone.mp3   ← Day 1  2025年12月 第一套 · Conversation One
audio/seg/2025-12-1_conversationtwo.mp3   ← Day 2  2025年12月 第一套 · Conversation Two
audio/seg/2025-12-1_passageone.mp3        ← Day 3  2025年12月 第一套 · Passage One
...
audio/seg/2023-06-2_recordingthree.mp3    ← Day 77 2023年6月 第二套 · Recording Three
```

| 项目 | 数值 |
|---|---|
| 数量 | 77 段 = 11 套 × 7 个 section（2023.06 – 2025.12，每年两套） |
| 时长 | 168–300 秒／段（含原文 + 念题 + 作答停顿） |
| 大小 | 1.0–1.8 MB／段，合计 **约 100 MB** |
| 编码 | mp3，24 kHz 单声道，48 kbps |

排序是**从新到旧**：2025.12 → 2025.06 → 2024.12 → 2024.06 → 2023.12 → 2023.06，
同一套内按考试顺序（Conversation One/Two → Passage One/Two → Recording One/Two/Three）。
这样默认 57 天备考期刚好把最近 8 套听完，最老的两套留作二刷。

文件名规则：`<套卷id>_<章节>.mp3`，章节取 `conversationone` / `conversationtwo` /
`passageone` / `passagetwo` / `recordingone`… 全小写无空格，和 `listening.json` 的 `audio` 字段一一对应。

> **为什么一段 3–5 分钟，不是整套 25 分钟？**
> 每天的四步精听只需要一个 section：太长听不完、挖空也做不完。
> 整套原文在「精听」页（`listen/` 目录），是纯文本 + 翻译，不占空间。
> 整套音频（约 314 MB）没有放进仓库——GitHub Pages 单仓库 1GB 上限，没必要为它占满。

> **为什么是 77 天不是 84 天？**
> 12 套 × 7 = 84，但 `2025.06 set2` 的录音把 25 个作答停顿整段剪掉了
> （1494.09 − 1156.30 = 337.8 ≈ 25 × 13.5 秒），分节边界无法可靠还原，
> 所以这一套没进每日听力，只留在「历年精听」里。

## 音频从哪来

从公开真题仓库下载的**整套原始音频**，按音频自己的停顿结构切出每个 section：

```
整段 → 8kHz 解码 → 1 秒 RMS 包络 → 找 ≥4 秒静音 → 断成 7 组（4/4/3/4/3/3/4）
     → 原文结束 = 本组第一个停顿起点 → 往前推「原文时长 + 10 秒」= 片段起点
     → 本组最后一个停顿结束 + 8.5 秒 = 片段终点
     → 24kHz 解码取子区间 → lamejs 编 48kbps mp3
```

`-ss` / `-to` 那套 ffmpeg 命令等价于上面最后一步，但**不能直接用**：源文件里有一半其实是
`.m4a` 套了 `.mp3` 的壳（文件头 `ftypM4A`），按 MP3 帧边界切会切坏，必须先解码成 PCM。

> ⚠️ **别信文件名里的套号。** 实测本地早年下载的 `cet6_2023_12_1.mp3` 实际内容是 2025.06 的音频
> （用 50ms RMS 能量包络做互相关比对确认，只有 2023.06、2024.12、2025.12 几套对得上）。
> 上游自己的 `build-data.mjs` 里也有 `audioOverrides` 在互换 2023.12 和 2025.06 的套号。
> 所以这些片段一律从**上游原始音频**切，不看文件名。

## 自己换音频 / 加新的一天

1. mp3 丢进 `audio/seg/`（名字随意，建议沿用上面的规则）
2. 改 `listening.json` 对应那天的 `audio` 字段，指向新文件
3. 按新音频重标每句的 `a`（起）/ `b`（止）秒数，以及 `dur`（总长）和 `qAt`（开始念题的位置）
4. `b` 建议比真实句末多给 0.15 秒，避免尾音被切掉

标时间轴的笨办法但很好用：浏览器打开音频，听到某句开头记下 `audio.currentTime`，一句一句记。

## 格式建议

- **mp3**（iOS / 安卓 / 电脑都能播），单声道、48–64 kbps 足够，语音不需要高码率
- 不建议 wav：文件大 5–10 倍，手机流量吃不消
- 采样率 24 kHz 对语音足够（人声主要能量在 4 kHz 以下），16 kHz 也够用，22.05/44.1 kHz 只会让文件变大

## 播放次数为什么只能 2 次

不是音频的限制，是 `js/app.js` 里自己写的播放器在数次数（`d.plays`，存在 `localStorage`）。
用原生 `controls` 做不到这件事，所以第 ① 步用的是自绘播放器；第 ③ 步换成 `data-act="play-free"`，不限次数。
