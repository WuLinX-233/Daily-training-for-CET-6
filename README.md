# CET-6 每日训练

纯静态单页应用。**没有后端、没有数据库、没有登录、没有构建步骤**，只有 HTML / CSS / JS + JSON + 音频文件。
所有路径都是相对路径，放在 `username.github.io/repo/` 这种子目录下也能正常跑。

| 模块 | 能力 |
|---|---|
| 单词闪卡 | **真题高频 1036 词优先**（高频没消化完不排扩展词）；每天词量自定义；点卡显示 **词性 / 音标 / 美式发音 / 真题出现次数 / 中文**；认识/不认识；不认识的次日优先复习 |
| 每日阅读 | 短文 + 长难句；**右键取词**（手机长按/点词），显示词性、音标、释义、发音；**按住右键划词**可查词组及用法；**选中任意一段文字**松手就整句翻译 |
| 每日听力 | 每天**一段真题音频（3–5 分钟，原文 + 念题）**，四步走：① 盲听做题（限播 2 次）② 精听填空（单句播放 + 核对）③ 原文翻译 ④ 连读弱读 |
| 历年精听 | 自由选**年份 + 套卷**，直接铺开整套逐行原文，每行下面「点击此处显示翻译」 |
| 每日翻译 | 输入框 + 参考译文；草稿自动存本地，刷新不丢 |
| 生词本 | 阅读取词 / 单词卡上**一键收词**；带原句语境；可标已掌握、复习模式、导出 CSV |

## 二、本地跑通（电脑 + 手机）

> **工作目录**：`D:\cet6` —— 既是仓库克隆，也是本地运行目录，也是 Pages 的发布源，一份东西三用。
> 桌面的「CET6训练」快捷方式 → `CET6训练启动器.bat`（`APP_DIR` 指向 `D:\cet6`），双击就能起服务。

> ⚠️ **不能双击 index.html 打开**。`file://` 协议下浏览器禁止读取本地 JSON，页面会提示加载失败。必须用本地服务器。

### 1. 电脑

双击 **`start-server.bat`**（需要装过 Python，`python --version` 能出结果就行），窗口会打印：

```
[电脑]  http://localhost:8000
[手机]  http://192.168.x.x:8000
```

浏览器打开 `http://localhost:8000` 即可。

> 它跑的是本目录的 `server.py`，而不是 `python -m http.server`。
> 原因：Python 自带那个**不支持 Range 请求**，音频拖进度条会卡住、部分手机浏览器干脆不播。
> `server.py` 补上了 206 Partial Content，行为和 GitHub Pages 一致。

### 2. 手机（同一个 WiFi）

1. 电脑上 `start-server.bat` 的窗口**别关**
2. 手机连**和电脑同一个 WiFi**
3. 手机浏览器输入窗口里打印的 `http://192.168.x.x:8000`
4. 连不上通常是 **Windows 防火墙**拦了：弹窗选"允许"，或到「允许应用通过防火墙」勾上 Python

### 3. 添加到主屏幕

- **iPhone**：Safari 打开 → 分享 → 添加到主屏幕
- **安卓**：Chrome → 右上角菜单 → 添加到主屏幕 / 安装应用

## 四、每日听力：四步怎么用

「听力」页每天只处理**一段真题**（3–5 分钟，是 7 个 section 之一，带 3–4 道题）。
11 套 × 7 个 section = 77 天不重复，按从新到旧排（Day 1 = 2025.12 第一套 Conversation One）。
顶部有四个步骤条，可以来回点，进度自动存本地。

### ① 盲听做题

- 页面只给**题目 + 选项 + 一个播放器**，不给原文、不给翻译
- **默认只能播 2 次**，播完按钮变灰，提示"播放次数已用完"（第 ③ 步不限次数）
- 音频是**原文 + 念题**连在一起的：原文念完之后，录音会逐题念出"Question 1… / Question 2…"，
  每题后面留 13–15 秒作答时间 —— 和考场上完全一样，所以**不要听到原文结束就关掉**
- 页面上会标出"题目从 x:xx 开始"，点「从题目开始听」可以直接跳过去，反复听题目
- 选完选项点「提交答案」→ 立刻显示**对错**（答对 N / M 题）和**每题解析**：
  正确答案、你选的、以及这道题答案在原文里的出处（那句原文 + 中文）

> 想放宽次数：`js/app.js` 里 `d.plays = 2` 的 `2` 改成你要的次数；已经做过的天数在 `localStorage` 里有记录，改完点"重置"或换一天。

### ② 精听填空

- 铺开这一段**全部原文**，其中 7–16 个关键短语被挖空（如 `[Not at all]`），挖空处是输入框
- 每行左边有个 **🔊 单句播放**按钮：只播这一句（`a`–`b` 秒），可以点无数次，反复听写
- 填完点「核对答案」：输入框变**绿**（对）或**红**（错，下面给出正确答案）
- 没挖空的行照样显示原文，也照样有单句播放按钮——上下文不断

### ③ 原文与解析

- 完整原文 + 逐句中文翻译（`line` 一行，中英对照）
- 这一步的播放器**不限次数**，可以边听边看

### ④ 连读弱读

按规则从原文里自动挑出**语音现象**并高亮，四类标签：

| 标签 | 触发规则 | 例子 |
|---|---|---|
| 连读 | 辅音结尾 + 元音开头 | `Not at all` → no-ta-tall |
| 失去爆破 | p/b/t/d/k/g 后面紧跟辅音 | `next day` 的 t 只做口型 |
| 闪音 | 两元音之间的 t/d | `a lot of` → a lodda |
| 弱读 | 虚词（of / to / for / and / can / have …） | `of` → /əv/ |

每条给出**原句片段 + 该怎么念 + 一句提示**，一天 70–80 条，够练了。

## 五、历年听力精听：怎么用

「精听」页顶部两个下拉框：**年份**（2023 / 2024 / 2025）→ **套卷**（该年第一套 / 第二套，或 6 月/12 月）。

选完立刻铺开**整套 145–150 行原文**：

- 一行一句，行首是说话人（`M` / `W`），按 `Conversation One` / `Passage Two` / `Recording Three` 分章节
- 每行下面有一块空白按钮 **「点击此处显示翻译」**，点一下出这一行的中文，再点一下收起
- 想一次全看：右上角「展开全部翻译」/「收起全部翻译」
- 这一页是纯读 + 翻译（练精读、对答案、抄句型用），音频练习在「听力」页

## 六、自由取词：选中多少翻译多少

在正文里用鼠标**选中任意一段文字**（手机上是长按拖选），松手就弹翻译 —— 一个词、半个句子、整段都行。

- 选中范围是**淡绿底色**，和取词卡片的蓝底区分开
- 浮层里是：原文（最多 3 行）+ 中文译文 + 按钮
  - **复制译文**：一键进剪贴板
  - **网页词典**：跳有道看这一段的详细解释
  - **＋ 生词本**：选中 4 个词以内才出现，直接把这个词组收进生词本
- 只选中**一个单词**时优先用本地词典（比机翻准、不联网），本地没有才走在线翻译
- 电脑上浮层跟着选区出现在下面（放不下就翻到上面）；手机上从底部弹出
- 点空白处 / 按 `Esc` 关闭

**翻译源**：MyMemory 免费接口（`api.mymemory.translated.net`，带 CORS，不需要 key、不需要后端）。
匿名额度约每天 5000 字符，个人用够了；额度用完会提示「今天的翻译额度用完了」，这时点「网页词典」也能查。
想换更好的接口，只改 `js/app.js` 里的 `translateText()`，返回中文字符串即可。

> 这个功能要求文字**可以被选中**，所以 `.w` 的 `user-select` 从 `none` 改成了 `text`。
> 右键划词查词组不受影响（右键拖动本来就不会产生原生选区）；有选区时点词也不会误弹单词卡。

## 七、生词本：怎么用

两个入口，收进同一个本子：

| 入口 | 操作 |
|---|---|
| 阅读取词 | 点一下 / 右键任意单词 → 浮层底部 **「＋ 加入生词本」** |
| 单词闪卡 | 点卡片翻到背面 → 中文下面 **「＋ 加入生词本」** |

- 收进来的是**词条原形**：点的是 `doses`，进本子的是 `dose`
- 顺手把**取词时所在的那一句原文**一起存下来，复习时能看回语境
- 再点一次按钮就是移出（文案会变成「✓ 已在生词本 · 点击移出」）
- 标签栏「生词本」上的数字 = 本子里**还没掌握**的词数

### 生词本页能做什么

- **全部 / 未掌握 / 已掌握** 三个筛选，可切换「按加入时间 / 按字母」排序
- 每条显示：单词、词性、音标、释义、原句、加入日期、来源（阅读 / 单词卡）
- 🔊 发音 · `✓ 标为已掌握`（只打标记，不删词）· `×` 移出本子
- **复习模式**：把未掌握的词过一遍，正面只给单词，点一下出释义和原句，再选 `还不熟` / `记住了`，过完给本轮统计
- **导出 CSV**：带 UTF-8 BOM，Excel / WPS 直接双击打开不乱码
- **清空**：二次确认后清空整个本子

> 本地词典没收录的词，收进来时释义可能是空的；打开生词本页会自动去在线词典补一次（补到就写回本地）。

## 八、数据维护（只改 JSON，不动代码）

### 核心规则

> **数组顺序 = 第几天。第 1 条就是 Day 1。**
> `date` 字段只用于显示，不参与"今天是第几天"的计算。
> 顶部显示的 `Day N / M`，`M` = **有内容的天数**（reading / listening / translation 里最长的那份）。

### 1. 词库 words.json

```json
{ "en": "environment", "zh": "环境，外界；围绕", "pos": "n.", "us": "inˈvaiərənmənt", "level": "难点", "fs": 77, "fc": 54, "fd": 13, "hf": 1 }
```

| 字段 | 含义 |
|---|---|
| `pos` `us` | 词性 / 美式音标（不带斜杠，界面自动加 `/ /`） |
| `level` | 来源分级标签（核心 / 基础 / 难点），纯展示，不参与抽词 |
| `fs` | 真题综合分（频次 × 覆盖篇数 × 覆盖月份 × 覆盖年份） |
| `fc` | 2020–2025 真题里出现多少 **次** |
| `fd` | 出现在多少 **篇**真题里 |
| `hf` | `1` = 真题高频词。**数组里带 `hf` 的排在前面**，抽词按数组顺序走，所以高频必然先学完 |

- 数组顺序 = 背诵顺序。当前是「1036 个高频词（按 `fs` 从高到低）→ 1451 个扩展词（保持原来的核心/基础/难点顺序）」
- 想调阈值重新算一遍：`python tools/mark-high-freq.py <cet6_high_frequency_words.csv> <阈值>`（默认 10）

### 2. 阅读 reading.json

```json
{
  "date": "2026-10-19",
  "title": "2026年6月 第3套 · Passage One",
  "passage": "整篇英文原文（真题 Section C 仔细阅读，374–709 词）……",
  "sentence": "从中挑一句长难句（必须是 passage 的连续子串）……",
  "analysis": "句子结构分析，用 \n 可以换行……"
}
```

`date` 是日历日期（Day 几就用第几条，按 `pickByDay` 取模循环）；`title` 是真题出处，显示在日期后面。`sentence` 必须能在 `passage` 里原样找到，否则页面高亮和取词会对不上——这是生成管线的硬校验项。

现在的 57 篇全部来自 2016–2026 年六级真题，出处见每条的 `title`。重新生成或扩充的方法见第十一节 4。

```json
  ],
  "questions": [
    { "q": "", "options": ["A) It is quite common", "B) It is rarely noticed"], "answer": "A", "at": 0 }
  ]
}
```

| 字段 | 作用 |
|---|---|
| `audio` | 相对路径，mp3 放 `audio/seg/` |
| `dur` | 音频总长（秒），播放器进度条按它画 |
| `qAt` | **开始念题目**的秒数（= 原文最后一句结束的位置）。第 ① 步靠它提示"题目从 x:xx 开始"，并给一个「从题目开始听」的跳转按钮 |
| `lines[].sp` | 说话人 `M` / `W`，没有就空字符串 |
| `lines[].t` | 这一句的英文原文 |
| `lines[].zh` | 这一句的中文翻译（第 ③ 步显示） |
| `lines[].a` / `.b` | 这句在音频里的**起止秒数**（单句播放靠它切） |
| `lines[].marks` | 原卷的题号标记（`[9]` 表示第 9 题念在这句附近），用于解析定位 |
| `lines[].cloze` | 第 ② 步的挖空模板：字符串 + `{ "a": "答案" }` 交替；**整行没有 `cloze` 就不挖空** |
| `questions[].answer` | 支持 `"B"` / `"b"` / 索引 `1` / 完整选项文本 |
| `questions[].at` | 这道题答案对应 `lines` 的下标，第 ① 步解析就引用这一句 |

- 六级听力的题目是**念在音频里**的（原文念完后逐题念 "Question 1…"，每题后 13–15 秒作答），
  试卷上只有选项，所以 `q` 一律留空，界面只显示"第 N 题"+ 四个选项
- **所以每段音频都必须把"念题"那段一起切进来**。只切到原文结束的话，做题时会发现"题目没念"，根本没法答。
  当前 77 段的切法是**按音频自己的结构**定的，不是按时间戳：
  每段原文后面固定跟 3–4 个「约 13 秒静音」（逐题作答时间），
  7 个 section 的停顿组数固定是 `4 / 4 / 3 / 4 / 3 / 3 / 4`，可以当结构指纹用（11 套全部命中）。
  原文结束 = 本组第一个停顿的起点；原文时长 = 转写最后一句 − 第一句；于是原文起点 = 原文结束 − 原文时长；
  片段 = [原文起点 − 10 秒（把"Questions X to Y…"的引子包进来）, 本组最后一个停顿结束 + 8.5 秒]。
  用这套办法算出来的 `lines[].a/b` 才是准的 —— 原来按时间戳标的版本，有的卷子整体偏了 10 秒甚至 100 秒
- 时间轴还有两种坑，都做了兜底：
  ① 个别句子跨度离谱（如 `[0, 134.5]` 把整段吞掉），按中位句长回推起点；
  ② 整卷时间轴**内部漂移**（各 section 的偏移量不一致），用「上一组停顿结束 → 本组停顿开始」的声学跨度
  反推真实时长，再把句时间按比例缩放；校验标准是语速落在 1.8–3.1 词/秒
- 想换成自己的音频：mp3 丢进 `audio/seg/`，`audio` 写相对路径，再把 `a`/`b` 秒数按新音频重标（`dur`、`qAt` 也改）

## 九、每天背多少词（页面里直接改）

「单词」页下方有设置区：**每天背几个词**，可用 −/+ 微调，也可直接输入 1–200，还有 10/15/20/30/44/50 快捷按钮。

- 词库 2487 词，想 57 天过一遍 → 每天约 **44** 个
- 改动后：本组还没开始答会立刻按新词量重抽；已经开始答则下一组生效

抽词规则（简化艾宾浩斯 + 高频闸门）：

1. **先复习**：以前标过"不认识"、还没变成"认识"的词优先占名额（按标记时间从旧到新）
2. **再上新词**：名额没满，从词库上次停下的位置往后取。**词库里高频词排在前面，所以前 1036 个新词全部是高频**
3. 标"认识" → 进已掌握，不再出现；标"不认识" → 明天自动出现在卡组最前面

### 高频闸门

"高频词学完了才学非高频词"是**硬闸门**，不是排序上的一句空话：

- 指针走到第 1037 个词时，如果高频词里还有没消化掉的（标了"不认识"还没转成"认识"），**当天这组一个扩展词都不排**，只排还没消化的高频词
- 所以某天可能只有 3 个词，做完就"本组完成"——这是故意的，就是在逼你把高频短板补掉
- 界面会在统计行和完成页提示"高频还剩 N 个没掌握"
- 高频全部掌握后，统计行变成 `高频 1036 / 1036`，然后才放开扩展词

**卡上的徽标**：`高频`（红）= 真题高频词，鼠标悬停能看到"2020–2025 真题出现 54 次 / 13 篇"；`扩展`（灰）= 真题低频或根本没出现过。

**改了词库顺序会怎样**：`js/app.js` 里有个 `WORDS_ORDER` 版本号，和 `words.json` 的顺序绑定。
改了数组顺序就把这个数字 +1，旧进度里的 `cursor` 自动归零、当天重抽，**但已掌握/待复习标记全部保留**，不会白背。

## 十、发音和取词是怎么实现的（不用后端）

- **单词发音**：直接请求有道词典发音接口 `dict.youdao.com/dictvoice?type=2&audio=单词`（type=2 是美音），用 `new Audio()` 播放，不需要后端、不需要 key
- **音标**：词库里的 `us` 字段（离线可用）
- **阅读取词**：短文在渲染时被切成 `<span class="w">`，监听 `contextmenu`（右键/长按）和 `mousedown(button=2)+mousemove`（按住右键划词），手机上点词也能查
- **在线兜底**：本地查不到时请求 `api.dictionaryapi.dev`（免费、支持跨域），给出音标 + 英文释义 + 发音
- **自由取词**：监听 `mouseup`（桌面）/ `selectionchange`（触屏），读 `window.getSelection()` 拿到选区文字，请求 `api.mymemory.translated.net` 翻译；选区在 `#main` 里、不在输入框里才触发
- **听力播放**：自己写的小播放器（不是原生 `controls`），这样才能数播放次数、按秒切单句；底层还是 `new Audio()` + `timeupdate` 看门狗

> 发音和在线兜底都需要联网。**断网时**：音标、释义、词组用法、听力原文/翻译/题目照常显示（都在本地 JSON 里），音频也在本地，只有发音按钮点不出声。

## 十一、数据是怎么来的

四份数据，五条管线，脚本都在 `tools/`：

### 1. 原文 / 题干 / 答案 ← Ysoseri1224 仓库

`CET6_2023.06/cet6_2023.06_set1_transcript.md` 里带 `[1]` `[2]` 题号，脚本按它把长段落切成句、
把题号挂到句子上（就是 `marks`），答案则**用选项文本配对**（两边的 A/B/C/D 排列经常不一样，直接搬字母会错位）。

### 2. 句级时间轴 + 中文翻译 ← getfine333-ux 仓库

`web/data/timestamps.json`（`cet6_2023.06_set1` → 每句起止秒）和 `web/data/translations.json`（按句子文本索引）。
切句规则和上游 `lib-sentences.mjs` 对齐（`Mr.` `U.S.` `a.m.` 之类缩写不断句、大写字母前瞻），
这样 `normalizeKey` 才能命中翻译表——实测 **1834/1834 句全部有译文**。

### 3. 每日听力切片 ← 上游原始音频

```bash
python tools/build-listen-data.py <真题仓库目录> <getfine 仓库/web/data 目录> [timestamps.json]
```

生成 `listen/index.json` + `listen/*.json`。

每日那 77 段 mp3 是从**上游原始整套音频**切出来的，24kHz 单声道 48kbps。
切之前先做三件事，顺序不能换：

1. **取包络**：把整段音频解码成 8kHz 单声道，算 1 秒一块的 RMS 能量包络（浏览器 `OfflineAudioContext` 干的，
   不用装 ffmpeg）。实测源文件里有一半其实是 `.m4a` 套了 `.mp3` 的壳（文件头 `ftypM4A`），
   按 MP3 帧边界切会直接切坏，所以必须先解码成 PCM 再处理
2. **找停顿**：阈值取 `5% 分位 + 0.12 × (95% 分位 − 5% 分位)`，找 ≥4 秒的静音段；
   相邻静音间隔 >45 秒就断组，最后应该得到 7 组、组大小 `4/4/3/4/3/3/4`
3. **切+编码**：按上一节的公式算 `start`/`end`，解码成 24kHz 单声道 PCM，
   取子区间，用 `lamejs` 编成 48kbps mp3（1152 采样一帧）

```bash
cd tools/listening
python dl.py            # 1. 并行 Range 下载 12 套源音频（~314MB，实测 3–6MB/s）
node analyze.js         # 2. 逐套解码，存 1 秒 RMS 包络到 env/
python build.py         # 3. 找停顿 → 算切点 → 生成 plan.json
python write_app.py     # 4. 写 ../listening.json 并自检
node cut.js             # 5. 按 plan.json 切 77 段（逐套解码一次，切 7 段）
node verify_all.js      # 6. 回读每段，确认 qAt 之后真有 3–4 个停顿
```

> 5、6 两步需要本地 HTTP 服务：`python srv.py . 8123`（带 Range，且要 `--noproxy`）。
> `cut.js` 用 `lame.all.js`（已随脚本放好），所以**不需要 ffmpeg**——机器上装不上 lameenc/numpy 时就是靠它。

> ⚠️ 别信"文件名 = 套号"。实测本机早年下载的 `cet6_2023_12_1.mp3` 其实是 2025.06 的音频
> （用 50ms RMS 能量包络做互相关比对确认），上游自己的 `build-data.mjs` 里也有 `audioOverrides` 在互换套号。
> 所以**音频一律从上游取**，不再依赖文件名。
>
> ⚠️ `2025.06 set2` 的录音把 25 个作答停顿整段剪掉了（1494.09 − 1156.30 = 337.8 ≈ 25 × 13.5 秒，
> 算术上对得死死的），但分节边界怎么拟合都对不上语速，所以这一套没进每日听力，只留在「历年精听」。

### 4. 每日阅读 57 篇 ← AndrewYuZhenYu/cet6_exam_questions_txt_collection

源是 `cet6_zhenti_cleaned/` 下 **62 个纯 TXT**（2016-06 → 2026-06），取每套 `Part III Section C`
的仔细阅读原文。这个库比看上去脏，三步都得容错：

1. **抽段落**（`extract.py`）——锚点用 `Questions 46 to 50 are based on the (following) passage`
   而不是 `Part III` / `Passage One`。实测 62 套里有 52 套缺 `Part III` 标题，但引导语几乎都在。
   结束条件用「遇到题号行 `46.` 或选项行 `A.`」，版式无关。
   实测只有 **19 套两篇都完整、34 套只剩一篇、9 套一篇都没有**（文件被截断，比如 `2023-06_01`
   第 24 题选项后直接跳到第 50 题），可用段落共 **60 篇**，够 57 天。
2. **选长难句**（`select.py`）——按「长度 + 从句标记 + 逗号/分号/冒号数」打分，取最高分。
   硬校验三条：必须是 `passage` 的连续子串、必须以大写开头、内部不能再出现句末标点
   （否则就是两句被 OCR 粘在一起）。过不了就顺位取下一候选。
3. **人工改选**（`finalize.py`）——自动选出来的句子里约 1/5 带 OCR 残迹
   （`krn`、`relig_ion`、`Ge nBan k`、`can more briskly across`），
   这些正则识别不了，只能人看一遍再指定候选下标。`OVERRIDE` 字典就是干这个的；
   若某篇三个候选全是残句，用 `SWAP` 整篇换成备用篇。

```bash
cd tools/reading
python fetch.py         # 1. 取回 62 个 TXT 到 data/（走 api.github.com + base64，

python extract.py       # 2. 抽 Section C 原文 → passages.json（60 篇）
python select.py        # 3. 打分选长难句 → picks.json（57 篇，每篇 3 个候选）
python finalize.py      # 4. 应用人工改选、分配日期 → entries.json
python merge.py         # 5. 合并 ana_0*.json 的解析 → ../reading.json 并自检
node test_reading.js    # 6. 浏览器里跑 10 项断言（需先起 srv.py）
```

`ana_01.json` … `ana_04.json` 是 57 条长难句解析（每条约 400–800 字），手写的，没有数据源能提供。

> ⚠️ **别信仓库的目录名。** `wamich/english-exem-md` 看起来最规整（markdown、按年份分目录），
> 但打开 `CET6/2023.06/cet6-2023-06-1.md` 第一行是「大学英语**四级**考试真题」，全文「六级」出现 0 次。

> ⚠️ 这个库**只有题目没有答案**。对阅读模块无影响——`reading.json` 的字段是
> `passage` / `sentence` / `analysis`，是精读 + 长难句分析，不是做题。
> 将来真要做「阅读做题」，得另找带答案的源（`0609x/CET46-Resources` 有答案解析 PDF，但是扫描件）。

### 5. 每日翻译 57 篇 ← xzyj50609/cet6-translation-writing-corpus

源是 `01_历年翻译真题_2015-2025/六级翻译全量题库_73篇.md`（22 069 字），

这个库比阅读那个干净得多，格式是规整的 markdown：


## 十二、数据存在哪

全部在浏览器 `localStorage`，键名 `cet6.v1`：

| 内容 | 说明 |
|---|---|
| `settings.dailyCount` | 每天词量 |

## 十三、常见问题

**Q：打开一片空白 / 提示"数据加载失败"？**
A：八成是双击了 `index.html`。用 `start-server.bat` 或部署后的网址打开。

**Q：改了 JSON，刷新没变化？**
A：① 检查 JSON 合法性（少逗号、多逗号、中文引号都会报错）；② 强刷 `Ctrl+F5`；③ GitHub Pages 等 1-2 分钟；④ 把 `sw.js` 里的 `VERSION` 加 1 强制更新缓存。

**Q：选中一段文字没反应 / 一直显示「翻译失败」？**
A：① 翻译要联网，断网就只有本地词典（单词还能查）；② MyMemory 的匿名额度约每天 5000 字符，用完了会提示「今天的翻译额度用完了」，第二天恢复；③ 一次最多翻 400 个字符，选太多只翻前面那段。实在查不到就点浮层里的「网页词典」。

**Q：生词本能换设备带走吗？**
A：和进度一样只存在这台设备的浏览器里。想带走就点生词本页的「导出 CSV」，或者控制台 `JSON.parse(localStorage.getItem('cet6.v1')).vocab` 复制出来。

**Q：听力第 ① 步播放按钮点不动 / 提示次数用完？**
A：设计如此，默认 2 次。想多听就点步骤条去第 ③ 步（那里不限次数），或者改 `js/app.js` 里的 `d.plays = 2`。
注意：**正在播放时再点按钮是"暂停"**，不消耗次数；只有从停止状态点"播放"才扣一次。

**Q：音频不播 / 显示"音频没加载出来"？**
A：按顺序查——
1. `audio/seg/` 里真的有那个文件吗？`listening.json` 的 `audio` 要和文件名**完全一致**（大小写、扩展名）
2. 路径写 `audio/seg/xxx.mp3`，不要用反斜杠
3. 浏览器直接打开 `http://localhost:8000/audio/seg/xxx.mp3` 能不能播？不能就是文件或服务器的问题
4. 用 `start-server.bat`（走 `server.py`），别用 `python -m http.server`——后者不支持 Range
5. iOS 侧边静音键拨到静音时 `<audio>` 会没声音；iOS 首次播放必须是用户点击

**Q：做题时听不到题目，只听到原文就结束了？**
A：说明那段音频只切到了原文结束。六级听力的题目是**念**出来的，位于原文结束后的那段空档里
（"Question 1…" 每题后留 13–15 秒）。重切规则见「八、3」：起点 = 停顿组首段起点 − 原文时长 − 10 秒，
终点 = 停顿组末段终点 + 8.5 秒。界面上的「题目从 x:xx 开始」和「从题目开始听」按钮就是按 `qAt` 定位的，`qAt` 标错也会跳错地方。

**Q：为什么每日听力是 77 天，不是 12 套 × 7 = 84 天？**
A：`2025.06 set2` 那套录音被剪掉了全部作答停顿（总长 1156 秒，比带停顿的版本短 337.8 秒 ≈ 25 × 13.5），
分节边界怎么拟合都对不上语速，所以这一套没进每日听力，只在「历年精听」里保留全文。
其余 11 套 × 7 个 section = 77 天，够默认 57 天的备考期用，还能留 20 天二刷。

**Q：换了一版 listening.json，之前听到第几天全清零了？**
A：设计如此。听力进度是按**天号**存的（`state.listening[day]`），篇目或顺序一变，旧进度就对不上了。
`js/app.js` 里有 `LISTEN_VER`，素材换一轮就 +1，旧进度整块作废——宁可重来，也不能让"第 3 天显示已完成、点开却是另一篇"。

**Q：单句播放播的是别的句子？**
A：`lines[].a` / `b` 是秒数，标错了就会串。改 `listening.json` 里那两个数字即可（`b` 可以稍微多给 0.15 秒，避免尾音被切）。

**Q：精听页点「显示翻译」没反应？**
A：那一行的 `zh` 是空的，按钮就不会渲染。检查 `listen/<id>.json` 里对应句的 `zh`。

**Q：点发音没声音？**
A：发音走有道接口，需要联网；离线时按钮会变淡。

**Q：右键取词在手机上怎么用？**
A：手机上**点一下单词**就会弹出底部卡片（安卓长按也可以）。想查词组，用电脑按住右键从左划到右。

**Q：为什么没有动画 / 夜间模式？**
A：刻意只做最小可用版本，稳定优先。
